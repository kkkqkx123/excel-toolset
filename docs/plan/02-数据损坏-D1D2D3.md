# 数据损坏修复方案：D1 / D2 / D3

**共同路径**：`excel-core` 的写流程 `calamine 读 → SheetData → rust_xlsxwriter 写`，CLI 与 HTTP 共用。这三处任何一处出错都会污染**所有**写产物。

---

## D1 — 写入空 `<f></f>`，第三方读取器判损坏

### 现象
任意"读后写"后，xlsx 中出现**空 `<f></f>` 元素**（T5.14、T9.15）；C#/ClosedXML 打开直接 `IndexOutOfRangeException`（T1.29、T9.16）。

### 根因
calamine 的 `worksheet_formula()` 对**普通单元格返回 `Some("")` 而非 `None`**。`read_sheet_all` 未过滤空串，空字符串被当成公式一路传到 `write_formula()`，写出 `<f></f>`。

```rust
// crates/excel-core/src/excel_read.rs:202
let formula = ws_formulas.as_ref().and_then(|f| {
    f.get_value((row_idx as u32, col_idx as u32))
        .map(|s| s.to_string())        // ← Some("") 直接通过，未过滤
});
```

同样问题存在于另外两个读取入口（`read_cell` 第 46 行、`read_range_with_options` 第 89 行）以及 `read_cell_formula` 辅助函数（第 180–188 行会把 `Some("")` 变成 `"="`）。
此外，`data_to_cell_data`（第 227 行）会把空公式塞进非公式单元的 `formula` 字段——但修复点统一在"提取公式"处过滤最简。

### 修改方案
在**所有**提取公式的位置加 `.filter(|s| !s.is_empty())`：

```rust
// read_sheet_all（第 202 行）
let formula = ws_formulas.as_ref().and_then(|f| {
    f.get_value((row_idx as u32, col_idx as u32))
        .filter(|s| !s.is_empty())     // ← 新增：过滤非公式单元
        .map(|s| s.to_string())
});

// read_cell（第 44 行）与 read_range_with_options（第 87 行）同样处理
let formula = ws_formulas
    .as_ref()
    .and_then(|f| f.get_value((row, col as u32))
        .filter(|s| !s.is_empty())
        .map(|s| s.to_string()));

// read_cell_formula 辅助函数（第 180 行）先判空再补 '='
fn read_cell_formula(...) -> Result<Option<String>> {
    ...
    Ok(formulas.get_value((row, col as u32)).and_then(|s| {
        let formula = s.to_string();
        if formula.is_empty() {          // ← 新增：空串视为无公式
            return None;
        }
        if formula.starts_with('=') { formula } else { format!("={}", formula) }
    }))
}
```

### 验证
- 用 openpyxl 生成含普通文本/数值的 `sales.xlsx`，执行任意写操作后，用 **ClosedXML（C#）打开**，不再抛 `IndexOutOfRangeException`。
- 直接解析产物 XML：`grep -c "<f></f>" out.xlsx` 应为 **0**（T1.29 复测）。

## D2 — 公式缓存值恒为 0

### 现象
`write_formula()` 从不调用 `set_result()`，rust_xlsxwriter 默认写 `<v>0</v>`。openpyxl `data_only=True` 读 `E2` 得 0（应为 55.0）；所有 `SUM/AVERAGE` 结果均为 0（T5.15）。

### 根因
```rust
// crates/excel-core/src/excel_write/core.rs:282
if let Some(ref formula) = cell.formula {
    ws.write_formula(row, col, formula.as_str())
        .map_err(AppError::Xlsx)?;
    return Ok(());      // ← 忽略 cell.value，写出默认 <v>0</v>
}
```

关键事实：`data_to_cell_data`（excel_read.rs:227）**已经把 calamine 的缓存值写入了 `CellData.value`**（公式单元格同时持有 `value=55` 与 `formula="=SUM(...)"`）。写路径只是没用上它。

### 修改方案（推荐：复用缓存值，零新增依赖）
```rust
// crates/excel-core/src/excel_write/core.rs:282
if let Some(ref formula) = cell.formula {
    let mut f = rust_xlsxwriter::Formula::new(formula.as_str());
    if let Some(ref v) = cell.value {
        // 复用读到的缓存值，避免 <v>0</v>；Formula::set_result 接受 impl Into<String>
        f = f.set_result(v.as_str());
    }
    ws.write_formula(row, col, f).map_err(AppError::Xlsx)?;
    return Ok(());
}
```
> `Formula::new` 会自动去掉前导 `=`（calamine 不含 `=`）；`set_result` 接受 `impl Into<String>`，直接传入缓存字符串即可。数值写成 `<v>55</v>`，字符串/布尔写成对应缓存文本，严格读取器通常会重算或接受。

**`write_cell_with_format`（core.rs:320+）存在同样的遗漏**，须同步修改（同一段 `if let Some(ref formula)` 逻辑）。

### 与 C4 的协同
对于**新写入、尚无缓存值**的公式（见 C4：CLI `formula set --eval` / `formula eval`），`cell.value` 为空，上述代码会退化为"写公式但无缓存值"。C4 方案会把这些路径计算出的结果写回 `CellData.value`，从而在此处自然获得 `set_result`。**两处一起修，公式缓存值在全部路径上都能正确落盘。**

### 验证
- 构造 `E2 = SUM(A2:D2)`，写后 openpyxl `data_only=True` 读 `E2` 应为 55.0（T5.15 复测）。
- 用 ClosedXML 打开写产物，所有公式单元格 `Value` 不再为 0。

## D3 — 工作表顺序随机化

### 现象
`HashMap` 迭代顺序非确定，每次写入后表顺序都变。原始 `[Sales, Config, Empty]`，实测出现 `[Config, Empty, Sales]` 等多种排列（T5.01）。

### 根因
```rust
// crates/excel-core/src/excel_write/core.rs:34（modify_file）与 :76（modify_file_with_wb）
let old_data = read_all_sheets_to_map(path)?;   // 返回 HashMap<String, SheetData>
...
for (name, data) in &old_data {                 // ← HashMap 迭代，顺序随机
    let ws = wb.add_worksheet();
    ws.set_name(name)...;
    write_sheet_data(ws, data)?;
}
```

### 修改方案（局部、零依赖：按 `list_sheets` 顺序遍历）
不改动 `read_all_sheets_to_map` 的返回类型，而在写工作表时按 calamine 的工作表原始顺序（`list_sheets` 保序）遍历：

```rust
// 在 modify_file 与 modify_file_with_wb 中，写工作表前取保序表名
let sheet_order = excel_read::list_sheets(path)?;
for name in &sheet_order {
    if let Some(data) = old_data.get(name) {     // 或 new_data.get(name)
        let ws = wb.add_worksheet();
        ws.set_name(name).map_err(AppError::Xlsx)?;
        write_sheet_data(ws, data)?;
    }
}
```

**可选增强（推荐）**：将 `read_all_sheets_to_map`（excel_read.rs:217）的 `HashMap` 换成 `IndexMap`（`indexmap` crate，插入序=表顺序），从源头保证所有消费方（写、diff）都拿到有序表。这同时让 diff 模块（F1）的表顺序稳定。若采用此方案，需同步调整 `modify_file`/`modify_file_with_wb` 的函数签名参数类型（`HashMap` → `IndexMap`），以及 `engine.rs`/`sheet_diff.rs`/`file_diff.rs` 中 `.into_values().collect()`（IndexMap 同样支持迭代，无需改动）。

### 验证
- 对 `[Sales, Config, Empty]` 三次连续写操作后 `list_sheets(out.xlsx)`，三次结果一致（T5.01 复测）。

## 工作量与依赖

| 项 | 改动量 | 新增依赖 |
|----|--------|----------|
| D1 | ~6 行（3 处提取点 + 1 处辅助函数） | 无 |
| D2 | ~4 行（2 处写公式逻辑） | 无 |
| D3 | ~8 行（2 处遍历）或 +`indexmap` 切换 | 可选 `indexmap` |

**三者合计约 1–2 小时（含编译 + 9 套件复测）**。均为根因修复，不含规避方案。
