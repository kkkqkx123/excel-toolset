# 文档校订方案（P3）

**范围**：`skills/excel/references/*.md` 与 `skills/excel-http/references/*.md` 中**字段名/结构与实现不符**的 20+ 处。照抄文档示例必定报错。本方案给出"文档写法 → 实际要求 → 建议修订"，供一次性校订。

> 信封类问题（H2/H3）在 [04-HTTP模块](./04-HTTP模块-H1H5.md) 已通过**改造代码对齐文档**解决，本文档仅处理**字段名/枚举/结构**偏差。坐标类（C5）在 [06-CLI缺陷](./06-CLI缺陷-C1C5.md) 已定方案。

## 校订执行建议

1. **以代码为权威**：每处修订前先用 `grep` 定位对应 handler / struct 的真实字段名（如 `old`/`new`、`comment`、`anchor_cell`、`rule_type`），以源码为准，不以记忆为准。
2. **批量替换**：CLI 与 HTTP 各准备一份"字段映射表"，对 `skills/**/*.md` 做定点替换；避免全文模糊替换误伤。
3. **示例可执行化**：校订后的每个示例应在 t1~t9 套件中**至少被一条用例覆盖**（报告中多项失败正是因为示例与实现不符却无人验证）。
4. **与代码修复联动**：本文档的字段修订须在对应代码修复（C2/C3/C5、H2/H4/H5、Q2/Q3）**合入后**进行，保证"文档 = 当前实现"。

## 工作量
纯文档校订，约 **1.5–2 小时**（含逐字段 grep 核对 + 示例可执行化复核）。无代码风险，但须与 [04](./04-HTTP模块-H1H5.md)/[06](./06-CLI缺陷-C1C5.md) 的代码改动**同步发布**，否则出现"新版代码 + 旧文档"或反之的二次偏差。
